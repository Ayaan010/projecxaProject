What is this page?

HIGH Severity Alerts
HIGH PORT_SCAN — Port Scan Detected
Why does this alert appear?

A single IP address sent packets to more than 15 different ports on your machine in a short time. The IDS counts unique destination ports per source IP; once the count exceeds the threshold, the alert fires and the counter resets.

Threshold is configurable in Settings → Port Scan Threshold (default: 15).

What could be causing it?
  • Reconnaissance scan — an attacker is mapping which services are running before attempting an exploit.
  • Automated scanner (Nmap, Masscan, ZMap) probing your IP range.
  • Vulnerability scanner (Nessus, OpenVAS) — could be legitimate IT security testing.
  • Worm/malware on another device on your network spreading laterally.
  • Misconfigured device retrying many ports repeatedly.
What happens if you block the IP?

✅ Safe to block in almost all cases.

  • All future packets from that IP are silently dropped before any detection runs.
  • The scan stops immediately — the attacker gets no responses, making your ports appear "filtered".
  • If it was a legitimate scanner (IT team, security audit), unblock it from the Alerts page.
  • Internal network devices (printers, IoT) could trigger this if misconfigured — verify the IP before blocking.
HIGH BRUTE_FORCE — Brute Force Attack
Why does this alert appear?

A single IP made more than 10 connection attempts to an authentication port within a 10-second window.

Monitored ports (login services):

{% for port, service in [ (21,'FTP'),(22,'SSH'),(23,'Telnet'),(25,'SMTP'), (110,'POP3'),(143,'IMAP'),(389,'LDAP'), (445,'SMB'),(3389,'RDP'),(5900,'VNC') ] %} {{ port }} {{ service }} {% endfor %}
What could be causing it?
  • Automated credential stuffing — bot trying millions of username/password combos from a leaked database.
  • Dictionary attack — trying common passwords (admin, 123456, password…).
  • Targeted SSH/RDP brute force — very common against internet-facing Linux/Windows servers.
  • Mirai-style IoT botnet scanning for default credentials on Telnet/SSH.
  • Misconfigured backup software retrying failed logins repeatedly (rare false positive).
What happens if you block the IP?

✅ Highly recommended to block.

  • Stops the brute force immediately — the attacker gets TCP RST or timeout instead of a login prompt.
  • Reduces server load from thousands of authentication attempts.
  • The attacker's progress is lost — they cannot resume the same session.
  • They may switch to a different IP — watch for the same pattern from new sources.
  • False positive risk is very low for this alert type.
HIGH TRAFFIC_SPIKE — High Traffic Rate
Why does this alert appear?

A single IP sent more than 100 packets within 5 seconds. That equals 20+ packets per second from one source — far above normal browsing traffic.

This is the alert most likely to trigger the block request popup you see at the top of the dashboard, since it fires repeatedly from flood sources. After 3 HIGH alerts from the same IP, a block confirmation is raised.

Thresholds adjustable in Settings → Packet Rate Threshold / Traffic Time Window.

What could be causing it?
  • UDP/ICMP flood (DoS) — attacker trying to overwhelm your bandwidth or CPU.
  • SYN flood — sending thousands of half-open TCP connections to exhaust connection tables.
  • Amplification attack — reflected traffic from DNS/NTP servers bounced at you.
  • Video streaming / large file transfer from a single device (legitimate, adjust threshold).
  • Backup job or cloud sync running on a local machine (false positive — check IP first).
  • Misconfigured game server or P2P client sending bursts.
What happens if you block the IP?

⚠️ Check the IP before blocking — false positive risk is moderate.

  • Blocking an external attacker: flood stops, CPU and bandwidth recover immediately.
  • Blocking a local backup server or NAS: that device's traffic will be completely silenced — you'll lose access to it too. Unblock from the Alerts page.
  • Blocking a streaming device: video/stream will stop working from that IP.
  • The block only applies within this IDS session — it does not add a firewall rule to your OS. Restart the IDS and the block is cleared.
MEDIUM Severity Alerts
MEDIUM SYN_SCAN — TCP SYN Scan
Why does this alert appear?

More than 20 TCP SYN-only packets arrived from this IP within 10 seconds without completing the handshake. Normal connections go SYN → SYN-ACK → ACK. A SYN scan floods SYN packets to many ports, notes which ones reply, then never sends ACK — so the connection is never established and many systems don't log it.

What could be causing it?
  • Nmap -sS (stealth scan) — the most common network scanner technique.
  • Pre-attack reconnaissance — identifying open ports before exploitation.
  • Legitimate network monitoring tools like Zabbix or Nagios checking host availability.
  • Retransmitted packets from a slow or unreliable connection (rare false positive).
What happens if you block the IP?

✅ Generally safe to block if from an external unknown IP.

  • The scanner gets no more responses — your ports appear completely filtered/closed.
  • If from a monitoring tool (Nagios, Zabbix), blocking it will make your host appear "down" in that system.
  • SYN scans alone don't harm you — but they are often a precursor to a targeted attack, so blocking is a good precaution.
MEDIUM SUSPICIOUS_PORT — Known Malware Port
Why does this alert appear?

Traffic was detected going to a port from a hardcoded suspicious list:

PortKnown for
4444Metasploit Framework default shell
1337Generic hacker/C2 tool convention
6666IRC botnets, some RATs
9999Generic backdoor / C2 servers

Add more ports in config.py → SUSPICIOUS_PORTS.

What could be causing it?
  • Active Metasploit session — an attacker has already compromised a machine and is using port 4444 for a reverse shell.
  • Remote Access Trojan (RAT) phoning home on port 6666 or 9999.
  • IRC-based botnet receiving commands on port 6666.
  • Developer testing — a developer running something like python -m http.server 4444 (false positive).
What happens if you block the IP?

✅ Block if you don't recognise the IP or the activity.

  • Cuts off the C2 channel — if malware on your network is phoning home, blocking the C2 server IP breaks the connection.
  • Does not remove the malware — you still need to investigate the machine that generated the traffic.
  • If from internal developer traffic, dismiss and update your suspicious ports list instead.
LOW Severity Alerts
LOW LARGE_PACKET — Unusually Large Packet
Why does this alert appear?

A single packet exceeded 1500 bytes — the standard Ethernet MTU (Maximum Transmission Unit). Normal traffic is fragmented to stay under this size. Packets over 1500 bytes are called "jumbo frames" and are unusual outside of specially configured networks.

Threshold adjustable in Settings → Large Packet Size.

What could be causing it?
  • Data exfiltration — attacker packing as much stolen data as possible into each packet to reduce the number of connections.
  • Fragmentation evasion — crafting oversized packets to confuse IDS/firewall fragmentation reassembly.
  • Jumbo frames — legitimate high-speed networks (storage, 10Gbe) configured with larger MTU (raise your threshold).
  • VPN or tunnel overhead — encapsulation adding extra headers pushes packets over 1500 bytes.
What happens if you block the IP?

⚠️ Low priority — investigate before blocking.

  • A single large packet is almost never an emergency on its own.
  • If the same IP also triggered HIGH alerts (port scan, brute force, traffic spike), blocking is justified.
  • If it's from a backup server, NAS, or VPN, blocking will break those services.
  • Consider raising the Large Packet Size threshold in Settings instead of blocking legitimate devices.
What exactly happens when you block an IP?
What blocking DOES do
  • All packets from that IP are dropped at the IDS input stage — before any detection logic runs, saving CPU.
  • The IP is added to the in-memory blocked list visible on the Alerts page.
  • A SYSTEM log entry is recorded with timestamp and reason.
  • No further alerts will fire from that IP for the rest of the session.
What blocking does NOT do
  • Does not add a firewall rule to Windows Defender Firewall, iptables, or any OS-level firewall. If the IDS is stopped, traffic from that IP flows freely again.
  • Does not persist across restarts — the blocked list is in memory only. Restart the IDS and all blocks are cleared.
  • Does not notify the attacker — packets are silently dropped, not rejected. The attacker may keep sending for a while.
  • Does not stop the attacker from switching IPs — a determined attacker can use a different address.
Tip: For a permanent block, use your OS firewall after confirming the threat. On Windows: netsh advfirewall firewall add rule name="Block <IP>" dir=in action=block remoteip=<IP>. On Linux: iptables -A INPUT -s <IP> -j DROP.
